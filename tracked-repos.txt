# ---------------------------------------------------------------------------
# Tracked repositories
# ---------------------------------------------------------------------------
# This file decides which repositories appear on the site. Nothing else does.
#
# Format: one `owner/name` per line. Blank lines are ignored, and everything
# from a `#` to the end of a line is a comment. The order of the lines is the
# order the cards appear in, inside their category.
#
# The card content itself (summary, highlights, stack, tier, category) lives in
# data/catalog.json. This file only answers the question "is it on the site?".
#
# To add a repository:
#   1. add its `owner/name` on a line below, under the right heading
#   2. run `python3 tools/build-catalog.py --fetch`, which pulls the repository
#      metadata from the GitHub API and appends a stub card to
#      data/catalog.json
#   3. open data/catalog.json and write the stub's tagline, summary and
#      highlights by hand, against the real repository
#   4. run `python3 tools/build-catalog.py` and commit all three files
#
# To remove a repository: delete its line, or comment it out, then re-run
# `python3 tools/build-catalog.py`. The card stays in data/catalog.json, so
# putting the repository back later costs one line rather than a rewrite.
#
# `--refresh` instead of `--fetch` also re-reads stars, language, topics and
# last-push date for the repositories that already have cards. The written
# parts of a card are never touched by either flag.
#
# `python3 tools/build-catalog.py --check` verifies that the generated
# assets/data/catalog.js and the project counts printed in index.html match
# this file. Continuous integration runs it, so an edit here that was never
# built fails the deploy instead of shipping a stale page.
# ---------------------------------------------------------------------------
